# 平衡滚球静态控制系统设计

## 1. 目标与范围

本设计面向 2026 年全国大学生电子设计竞赛 H 题“车载平衡滚球运动控制系统”的第一阶段开发。第一阶段仅处理小车静止时的钢球定点控制，依次实现摆杆中心 `0 cm`、`+5 cm` 和 `-5 cm` 三个目标位置；车辆行驶扰动补偿留到第二阶段。

题目相关指标如下：

- 摆杆约长 `25 cm`，管内钢球直径约 `1 cm`。
- 钢球从中心移动至 `+5 cm` 或 `-5 cm` 指定位置并稳定，调节时间小于 `5 s`。
- 指定位置控制的最大位置偏差小于 `1 cm`。
- 后续车辆行驶过程中，钢球相对中心或指定位置的最大偏差也要求小于 `1 cm`。

第一阶段不实现理论连杆逆解、LQR、卡尔曼滤波、自适应控制或车辆加速度前馈。设计重点是先建立安全、可调试、可扩展的静态闭环基线。

## 2. 已知硬件条件

### 2.1 主控制器与串口

- 主控制器为 STM32F103C8T6，系统时钟 `72 MHz`。
- 工程已配置 USART1、USART2、USART3，波特率均为 `115200`，收发方向均配置 DMA。
- 当前应用层基本为空，尚无摄像头协议、步进驱动协议和闭环控制实现。

### 2.2 位置测量

- 摄像头通过串口返回钢球沿摆杆方向的一维有符号位置，单位为 `cm`，数据类型为浮点数。
- 位置以摆杆中心 `O` 为 `0 cm`，两侧分别为正、负方向。
- 摄像头刷新率约为 `35 Hz`，即平均帧周期约 `28.6 ms`。
- 钢球静止时的位置抖动小于 `±0.1 cm`。
- 摄像头端到端测量延迟尚未测量，必须在闭环调参前完成测量。

### 2.3 执行机构

- 步进电机通过串口驱动，命令同时支持位置、速度和加速度参数。
- 新位置命令能够立即覆盖当前尚未完成的运动目标。
- 步进电机驱动偏置曲柄滑块机构的曲柄主轴，曲柄推动连杆和齿条往复运动，齿条最终带动摆杆。
- 曲柄只在人工水平零位附近有限角度正反摆动，不连续旋转。
- 连杆映射存在非线性，但当前无法测量或标定摆杆实际倾角。
- 系统没有绝对零位、限位开关或摆杆角度反馈，只能人工调平后把当前位置定义为软件零位。
- 当前不知道机构安全运动范围，但 STM32 可以从很小的相对位置范围开始限制命令并逐步试验。

由于缺少实际摆杆角度，控制输出不定义为物理倾角，而定义为曲柄相对人工零位的驱动器位置单位。零位附近机构必须保持单调，并远离曲柄滑块机构的两个死点。

### 2.4 惯性传感器

- 惯性传感器安装在小车上，不随摆杆旋转。
- 传感器某一轴与摆杆水平方向保持一致，理论上可测量车辆沿摆杆方向的加速度扰动。
- IMU 串口协议和输出内容尚未确定。
- 第一阶段保留 IMU 接口但不使用其数据参与控制。

## 3. 方案选择

采用“位置与速度状态反馈 + 小积分 + 驱动器位置执行”的方案：

```text
摄像头球位置
-> 数据校验
-> alpha-beta 观测器估算球位置和球速度
-> Kp 位置反馈 + Kv 速度阻尼 + Ki 小积分
-> 曲柄相对目标位置
-> 位置、速度、加速度限制
-> 步进驱动器
```

该方案比单纯位置式 PID 更适合当前系统：球位置到机械倾斜控制量近似为二阶动态，显式球速反馈能够提供阻尼；积分只负责消除机械偏置和小静差，避免成为主要控制量。与模型控制相比，该方案不依赖当前无法获得的摆杆角度和精确连杆模型。

## 4. 控制数据流

### 4.1 更新时机

闭环控制由新的有效摄像头帧触发，约为 `35 Hz`。控制器不得在高速定时循环中重复使用同一位置帧进行积分，也不得在通信恢复后按队列补算过期帧。

每次更新使用相邻有效帧的实际时间间隔 `dt`，不能固定假设为 `1/35 s`。`dt` 超出合理范围时应重置观测器速度状态或拒绝该次更新。

### 4.2 alpha-beta 观测器

设上一帧估计位置和速度为 `x_hat`、`v_hat`，当前摄像头测量为 `x_camera`：

```text
x_predict = x_hat + v_hat * dt
residual  = x_camera - x_predict
x_hat     = x_predict + alpha * residual
v_hat     = v_hat + beta / dt * residual
```

变量单位如下：

- `x_camera`、`x_hat`：`cm`
- `v_hat`：`cm/s`
- `dt`：`s`
- `alpha`、`beta`：无量纲参数

第一帧或长时间丢帧后，以当前测量初始化 `x_hat`，并将 `v_hat` 清零，避免恢复瞬间产生虚假速度尖峰。由于静态噪声小于 `±0.1 cm`，只使用轻度滤波，避免额外相位延迟。

### 4.3 状态反馈控制

目标位置经过斜坡限制后记为 `x_target`：

```text
error = x_target - x_hat
u_raw = Kp * error - Kv * v_hat + Ki * integral
```

其中 `u_raw` 的单位是驱动器相对位置单位，不代表摆杆角度。控制方向由独立参数 `control_sign` 表示：

```text
u_signed = control_sign * u_raw
```

`control_sign` 必须通过低速、小位移开环试验确定，不得依靠把 PID 参数改成负数来掩盖方向问题。

### 4.4 积分策略

首轮调试令 `Ki = 0`，先完成 PD 控制。仅在 PD 响应稳定后加入很小的积分。

积分只在以下条件全部满足时更新：

- 当前摄像头数据有效且未超时。
- 系统处于闭环运行状态。
- 位置误差位于设定的积分作用区间内。
- 输出没有沿误差推动方向发生饱和。

积分状态必须单独限幅。在目标切换、退出闭环、发生故障或观测器重新初始化时清零积分。

### 4.5 输出限制

控制输出依次经过以下约束：

```text
方向修正
-> 相对软件零点的绝对位置限幅
-> 每帧最大目标位置变化量限制
-> 驱动器速度限制
-> 驱动器加速度限制
```

初始安全范围从很小的 `±u_safe` 开始，只有在无球开环试验确认无碰撞、无卡死并远离死点后才能逐步扩大。所有目标均发送为相对于本次人工零点的绝对位置，避免累计相对命令造成漂移。

驱动器的速度和加速度限制在第一阶段采用固定、保守参数。STM32 主要更新目标位置，利用驱动器“新目标立即覆盖旧目标”的能力避免旧命令排队。

### 4.6 目标位置管理

`0 cm`、`+5 cm` 和 `-5 cm` 使用同一套控制器，只改变设定值。目标位置不能阶跃切换，应通过斜坡生成器逐渐变化。初始可从 `1 cm/s` 至 `3 cm/s` 的目标变化速度开始试验，再依据调节时间和超调调整。

## 5. 软件组件

软件按职责划分为以下独立组件：

- 摄像头协议解析器：从 DMA 接收数据中提取完整帧，校验格式并生成带接收时间的数据对象。
- 球状态观测器：实现 alpha-beta 位置和速度估计，不依赖 HAL 或串口。
- 平衡控制器：实现状态反馈、条件积分和参数管理，不直接发送串口。
- 目标管理器：选择 `0 cm`、`+5 cm`、`-5 cm` 并实现斜坡目标。
- 执行器限制器：处理方向、目标位置、每帧变化量、速度和加速度限制。
- 步进驱动协议层：编码驱动命令、处理状态或故障响应。
- 安全状态机：管理人工调平、开环检查、闭环和故障状态。
- 遥测模块：输出调试变量，不参与控制决策。

中断和 DMA 回调只负责接收、确认缓冲区边界和投递完整数据，不在回调中运行浮点控制算法，也不执行阻塞式串口发送。

## 6. 状态机

系统采用以下状态：

```text
BOOT
-> WAIT_MANUAL_ZERO
-> OPEN_LOOP_CHECK
-> READY
-> CLOSED_LOOP
-> FAULT
```

### 6.1 BOOT

初始化 UART、DMA、控制参数、观测器和驱动器。此状态不得发送闭环目标。

### 6.2 WAIT_MANUAL_ZERO

电机不执行闭环动作，由操作者将水管人工调至水平。操作者按键确认后，把当前驱动器位置定义为本次运行的软件零点。

MCU 复位后不得沿用复位前的软件零点，必须重新人工调平确认。

### 6.3 OPEN_LOOP_CHECK

使用远小于最终安全范围的正、负相对位置试动，验证：

- 电机通信可用。
- 正负方向与控制坐标约定一致。
- 机构无碰撞、卡死或接近死点现象。
- 新目标能够覆盖旧目标。

首版可由操作者确认结果，不自动推断机械安全性。

### 6.4 READY

执行器回到软件零点，等待操作者选择目标并启动闭环。进入闭环前必须已有连续有效的摄像头数据。

### 6.5 CLOSED_LOOP

只在收到新的有效摄像头帧时更新观测器、积分器和目标位置。旧帧只可用于保持当前执行器目标，不可重复参与控制计算。

### 6.6 FAULT

停止生成新的闭环目标，清零积分，并要求人工检查和重新调平。首版默认保持驱动器当前目标和保持力矩，不自动高速回零；保持与缓慢回中的最终选择必须经过实机安全测试。

## 7. 故障与边界处理

以下任一条件触发故障或禁止进入闭环：

- 摄像头坐标超出水管的合理物理范围。
- 超过约 `100 ms` 未收到有效的新位置帧；最终阈值根据实测延迟和帧间抖动确定。
- 摄像头协议解析连续失败、帧序号重复或明显跳变。
- 电机串口发送持续失败，或驱动器返回故障状态。
- 输出长期饱和而钢球仍持续远离目标。
- 钢球进入靠近水管端部的保护区域。
- MCU 或看门狗复位。
- 操作者触发急停。

数据异常处理应遵循以下原则：

- 丢失或无效位置不能替换为 `0 cm`。
- 长间隔后的首帧不能直接与旧帧差分估速。
- 串口恢复后只使用最新完整帧，不补算积压帧。
- 故障状态下不继续积分。

## 8. 串口协议要求

具体协议待用户提供后确定。摄像头协议至少应能表达：

```text
frame_id, timestamp_ms, valid, position_cm
```

若摄像头不能提供源端时间戳，STM32 至少记录接收完成时间；若不能提供 `valid` 字段，必须约定不会与有效坐标冲突的丢球表示。协议还需定义帧头、长度、字节序、校验方式和浮点编码方式。

步进驱动协议需明确：

- 绝对位置、速度、加速度的单位和合法范围。
- 命令帧格式及校验方式。
- 最大命令刷新率。
- 新目标覆盖行为。
- 停止、保持、失能的区别。
- 是否返回当前位置、忙状态、到位状态和故障码。

建议串口职责如下：

- USART1：摄像头位置输入。
- USART2：步进驱动器命令和状态。
- USART3：第一阶段调试遥测；第二阶段根据资源安排切换或复用为 IMU 输入。

最终端口分配可根据实物接线调整，但协议解析和控制器不得依赖固定 UART 实例。

## 9. 调试与验证流程

### 9.1 摄像头链路

- 验证平均刷新率约为 `35 Hz`。
- 记录帧间隔分布、丢帧率和最长帧间隔。
- 验证坐标零点、正负方向和有效物理范围。
- 测量球实际运动到 STM32 收到对应坐标的端到端延迟。
- 验证丢球时不会输出伪造的 `0 cm`。

### 9.2 执行器开环

- 无球状态下人工调平并确认软件零点。
- 以极小正、负位置试动确认控制方向。
- 确认目标覆盖，不产生旧命令排队。
- 测量最小有效位置变化、换向回差和通信延迟。
- 从很小范围逐步扩大 `u_safe`，确认机构不碰撞且远离死点。

### 9.3 钢球开环响应

- 给出很小的正、负曲柄位置阶跃。
- 确认钢球运动方向与负反馈符号。
- 记录球开始运动的延迟和局部响应强度。
- 检查正、负方向响应是否明显不对称。

### 9.4 闭环调参

1. 令 `Ki = 0`、`Kv = 0`，从极小 `Kp` 开始，确认闭环方向正确。
2. 增大 `Kp`，直到钢球回归明显且接近出现振荡趋势。
3. 增大 `Kv` 提供阻尼，降低振荡和超调。
4. 验证中心 `0 cm` 控制。
5. 在近目标区域加入很小的 `Ki` 消除残余静差。
6. 依次验证 `+5 cm` 和 `-5 cm`，调整目标斜坡速度。
7. 多次往返并在重新人工调平后重复测试，评估零点敏感性。

### 9.5 记录指标

每次测试至少记录：

- 首次进入 `±1 cm` 误差带的时间。
- 进入误差带后是否再次离开。
- 最大超调和稳态峰峰值。
- 输出饱和比例和持续时间。
- 摄像头丢帧率、最长帧间隔和测量延迟。
- 原始位置、估算位置、估算速度、设定值、误差、控制输出、限幅标志和状态机状态。

第一阶段完成标准为：在静止小车上，中心和 `±5 cm` 三个目标均能重复稳定，指定点调节时间小于 `5 s`，最大位置偏差小于 `1 cm`，且异常数据和通信中断不会驱动机构持续越界。

## 10. 第二阶段 IMU 扰动前馈

车辆行驶阶段保留基础反馈环，在其输出端叠加车辆轴向加速度前馈：

```text
原始加速度和角速度
-> 静态零偏校准
-> 姿态估计与重力补偿
-> 投影到摆杆水平方向
-> 低通和限幅
-> Kff * 轴向加速度
-> 叠加到反馈控制输出
```

加速度计测量车辆线加速度与重力投影的合量；陀螺仪测量角速度，不能直接替代线加速度。由于 IMU 固定在车体上而不随摆杆转动，它不能测量摆杆实际倾角，也不能检测步进电机丢步。

IMU 模块第一版协议建议至少返回：

```text
timestamp_ms, ax, ay, az, gx, gy, gz
```

如果模块提供可信的姿态融合，可额外返回四元数，但应保留原始数据用于坐标系、重力补偿和振动问题排查。前馈增益 `Kff` 从 `0` 开始逐步增加；坐标方向、时间同步和重力补偿未验证前必须保持关闭。

## 11. 待协议到位后确定的参数

下列事项在当前设计中有明确接口，但数值需在协议和实物测试后确定：

- 摄像头和步进驱动器的二进制或文本帧格式。
- 摄像头端到端延迟、异常值阈值和超时阈值。
- `alpha`、`beta`、`Kp`、`Kv`、`Ki` 及积分作用区间。
- 曲柄软件安全范围 `u_safe` 和每帧最大目标变化量。
- 驱动器速度、加速度和停止方式。
- 目标斜坡速度。
- 水管端部保护位置。
- 第二阶段 IMU 协议、滤波参数和前馈增益。

这些参数必须通过上述分阶段试验获得，不能在缺少实测依据时假定为最终值。

# Emm V5 步进电机驱动移植设计

## 1. 目标与范围

将 `../temp/SM.c` 和 `../temp/SM.h` 中的 Emm V5 串口步进电机协议移植到当前 `balanceBall` 工程，并连接现有平衡控制执行器输出。

本次移植遵循以下边界：

- 不修改 `../temp/SM.c` 和 `../temp/SM.h`，它们只作为协议参考源。
- 当前硬件为一台 Emm V5 系列步进电机驱动器，通过 USART2 通信。
- 移植临时驱动覆盖的完整有效协议功能，并增加平衡执行器适配。
- 人工将机构调平后，读取驱动器实时位置并将其记录为本次运行的软件零点。
- 不在启动时写入细分参数，不自动回零，也不自动发送试动命令。
- 本轮以主机单元测试和 ARM 交叉编译通过为验收标准，实机联调另行进行。

## 2. 现状与移植原因

临时驱动包含使能、速度、位置、快速位置、同步触发、状态查询、参数设置、停止和回零等 Emm V5 命令，但不能直接合入工程：

- `SM_PulseToRate()` 使用未定义的 `angular_velocity` 和 `rate`，当前代码不能通过编译。
- UART、协议编码和电机运行状态耦合在同一个结构体中，无法脱离 HAL 做协议测试。
- 发送宏在调用 `HAL_UART_Transmit_DMA()` 后固定延时 `1 ms`，没有依据 DMA 完成事件管理发送缓冲区生命周期。
- 环形发送槽位会直接轮转，不能保证再次使用某个槽位时对应 DMA 已经完成。
- 接收启动后立即读取响应缓冲，没有等待 Receive-to-Idle 完成。
- 参数使用普通 `int`，没有定义协议字段宽度、合法范围及溢出规则。
- 初始化固定绑定 USART1、地址 `0x01`、128 细分并立即使能，不符合当前 USART2 分配和安全启动要求。

因此，本次移植保留经过核对的协议帧定义，但重写模块边界、传输生命周期、参数校验和错误处理。

## 3. 方案选择

采用“纯协议核心 + USART2 DMA 事务层 + 平衡执行器适配层”的三层设计。

未选择整体复制 `SM` 驱动，因为该方式会继续保留协议、HAL、状态和缓冲生命周期之间的耦合。未选择阻塞式 UART，是因为通信异常可能阻塞约 `35 Hz` 的控制链路和安全状态机。

## 4. 软件架构

### 4.1 Emm V5 协议核心

新增：

- `App/Inc/emm_v5_protocol.h`
- `App/Src/emm_v5_protocol.c`

该模块为不依赖 STM32 HAL 的纯 C 模块，负责：

- 编码使能控制 `0xF3`。
- 编码速度控制 `0xF6`。
- 编码位置控制 `0xFD`。
- 编码快速位置参数 `0xF1` 和快速位置运动 `0xFC`。
- 编码多机同步触发 `0xFF`。
- 编码实时位置查询 `0x36` 和状态查询 `0x3A`。
- 编码细分设置 `0x84`、停止 `0xFE`、单圈零点设置 `0x93`、触发回零 `0x9A`、退出回零 `0x9C` 和 PID 读取 `0x21`。
- 解析普通 ACK、实时位置、状态和 Emm 格式 PID 响应。

协议接口使用 `uint8_t`、`uint16_t`、`uint32_t` 和 `int32_t` 等定宽类型。编码函数接收调用方缓冲区及容量，返回结果状态和实际帧长。编码前检查地址、字段范围和缓冲区容量，不依赖全局 UART 或全局发送缓冲。

协议尾字节固定为 `0x6B`。多字节速度、位置和 PID 字段按临时驱动现有协议采用高字节在前的顺序。

### 4.2 USART2 DMA 事务层

新增：

- `App/Inc/emm_v5_uart.h`
- `App/Src/emm_v5_uart.c`

该模块绑定由 CubeMX 初始化的 `huart2`，负责：

- 持有在 DMA 完成前保持稳定的 TX 缓冲区。
- 启动和管理 Receive-to-Idle DMA 接收。
- 一次只允许一个在途事务。
- 根据发送完成、接收完成、UART 错误和超时事件推进事务状态。
- 校验响应是否与请求地址和功能码匹配。
- 向应用层报告完成、忙、超时、协议错误、驱动器错误和 HAL 错误。

HAL 回调只向事务层投递完成或错误事件，不进行浮点计算、不编码下一条控制命令，也不执行阻塞延时。需要修改 CubeMX 生成文件时，只在其 `USER CODE` 区域加入回调分发调用。

### 4.3 平衡电机适配层

新增：

- `App/Inc/balance_motor.h`
- `App/Src/balance_motor.c`

该模块负责把现有 `BalanceActuatorCommand` 转换为 Emm V5 位置命令，并管理人工软件零点：

- 初始化只建立软件状态，不自动使能或运动电机。
- 操作者完成人工调平并确认后，发起实时位置查询。
- 成功解析位置响应后，将驱动器当前位置记录为 `zero_position`。
- 未确认软件零点时拒绝所有普通位置命令。
- 把 `position`、`speed` 和 `acceleration` 转换为协议字段。
- 发送 `0xFD` 绝对位置、立即执行命令。
- 对上层暴露明确的就绪、忙、故障和零点状态。

现有 `balance_actuator` 和 `balance_loop` 保持硬件无关。本轮提供适配 API 和构建接入，但不在 `main()` 中自动使能、调零或试动机构。

## 5. 数据流

### 5.1 启动和软件零点

1. CubeMX 初始化 GPIO、DMA 和三个 UART。
2. 应用初始化协议事务层和平衡电机适配层，不发送运动命令。
3. 操作者将机构人工调平并显式确认。
4. 适配层通过 USART2 发送实时位置查询 `Addr 36 6B`。
5. 事务层等待 Receive-to-Idle 回调并校验完整响应。
6. 适配层保存有符号驱动器当前位置为 `zero_position`，随后才允许位置控制。

MCU 复位后软件零点失效，必须重新人工调平并确认。驱动器内部位置可以持续存在，但不能直接作为已经确认的机械水平零点。

### 5.2 执行位置命令

控制输出表示相对于人工水平零点的有符号位置偏移。适配层计算：

```text
target_position = zero_position + relative_position
```

该加法使用显式的 `int32_t` 边界检查，不允许整数回绕。位置字段的最终方向和幅值遵循 Emm V5 `0xFD` 命令定义：方向由目标位置相对协议坐标的符号确定，四字节位置字段编码非负幅值。

速度和加速度由 `BalanceActuatorCommand` 提供，转换和舍入规则固定且可测试。超出协议合法范围时拒绝命令，不静默截断为另一个运动参数。

### 5.3 最新目标覆盖

UART DMA 同一时刻只发送一帧。如果控制器在发送期间产生多个新位置目标，适配层只保留最新目标，不建立历史位置队列。当前发送完成后立即发送最新目标，避免过期闭环命令依次执行。

停止、故障处理和失能命令的优先级高于普通位置目标。提交这些命令时清除尚未发送的普通目标。

查询类命令必须等待并解析对应响应。位置命令 ACK 由事务层解析和记录，但不能让旧位置目标阻塞最新闭环目标无限期发送；具体超时后进入错误状态，不继续无界重试。

## 6. 错误处理与安全规则

- 未确认软件零点时拒绝位置命令。
- 地址、功能码、响应长度或帧尾 `0x6B` 不匹配时拒绝响应。
- 驱动器返回 `0xE2` 或 `0xEE` 时报告驱动器错误，不视为成功 ACK。
- DMA 忙、UART 错误和响应超时分别记录为可辨别的状态。
- 连续通信失败达到配置阈值后锁定普通运动输出。
- 清除通信故障后仍需重新确认人工零点，才能恢复普通位置输出。
- 停止命令默认停止运动并保持驱动器使能和保持力矩，不自动失能，也不自动高速回零。
- 通信层不在中断回调中执行阻塞发送、延时或控制算法。
- 所有协议数组访问都先验证实际帧长，避免读取未完成或过短响应。
- 不在每次启动时写驱动器 Flash 参数，以减少误配置和存储擦写。

## 7. 构建集成

`CMakeLists.txt` 加入三个新模块的源文件；头文件继续放入现有 `App/Inc` include 路径。测试目标单独编译纯协议模块和适配层逻辑，STM32 固件目标编译 USART2 DMA 实现。

如果现有测试构建尚未抽象 HAL，适配层通过窄传输接口接收发送函数和上下文，使主机测试可以使用伪传输实现，而不需要链接 STM32 HAL。

`../temp` 不加入 include 路径和构建源文件列表，确保参考原件不会被工程误编译或间接修改。

## 8. 测试设计

### 8.1 协议单元测试

- 对临时驱动覆盖的每类命令做逐字节期望帧测试。
- 验证地址、功能码、同步标志和帧尾。
- 验证速度、位置和 PID 字段的大端编码与解析。
- 验证零、正负位置和 `int32_t` 边界附近输入。
- 验证非法参数、空指针和输出缓冲不足均返回错误。
- 验证普通 ACK 的成功、条件成功、冲突和错误状态。
- 验证实时位置、状态和 Emm 格式 PID 响应。
- 验证截断帧、错误地址、错误功能码和错误帧尾被拒绝。

### 8.2 适配层单元测试

- 验证没有软件零点时拒绝位置命令。
- 验证读取当前位置后建立软件零点。
- 验证正负相对位置转换为正确绝对目标和方向。
- 验证软件零点加偏移的溢出检测。
- 验证浮点位置、速度和加速度的舍入规则。
- 验证发送忙时只保留最新位置目标。
- 验证停止命令清除待发送普通目标并优先执行。
- 验证通信故障锁定运动输出并使软件零点失效。

### 8.3 回归与固件构建

- 运行现有 `tests/test_balance.c`，确认控制核心无回归。
- 运行新增主机单元测试，确认协议和适配逻辑通过。
- 运行 ARM CMake 交叉编译，确认 USART2、DMA 和 HAL 回调集成可链接。

## 9. 本轮不包含的工作

- 不自动执行电机使能、试动、回零或闭环运行。
- 不确定最终机械安全位置范围、速度和加速度参数。
- 不进行实机方向、通信时序、响应码或最大刷新率验证。
- 不改变摄像头 USART1 和调试或 IMU USART3 的职责分配。
- 不修改现有控制算法或 PID 参数。
- 不更新用户验收后才需要同步的项目发布说明和实机调试文档。

上述事项需要在固件通过编译与单元测试后，通过低速、小位移、无球的实机流程单独验证。

## 10. 完成标准

- `../temp/SM.c` 和 `../temp/SM.h` 保持未修改。
- 完整 Emm V5 协议编码和本项目需要的响应解析由纯 C 模块提供。
- USART2 DMA 传输具有明确的缓冲生命周期、单事务状态和超时处理。
- 平衡执行器命令可以在确认软件零点后转换为安全检查过的绝对位置命令。
- 启动固件不会自动驱动机构。
- 现有测试、新增测试和 ARM 交叉编译全部通过。

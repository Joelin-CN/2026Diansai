## 🐛 重点一：停止模式为"滑行"而非"制动"（已修复）

### 发现过程

停止测试（`Motor_SetSpeed(0, 0)`）后，电机继续高速滑行：
- 从40%速度停止后，左轮在2s内仍累计 **100,940** 个计数
- 右轮累计 **37,860** 个计数
- 结论：TB6612没有施加任何制动力，电机完全靠摩擦自然减速

### 根因：TB6612 真值表理解错误

**TB6612 完整真值表（单通道）：**

| IN1 | IN2 | PWM | 输出模式 | 说明 |
|:---:|:---:|:---:|:-------:|------|
|  L  |  L  |  X  | **Stop（Coast，高阻）** | ← 原代码的实现 |
|  H  |  H  |  X  | **Short Brake（制动）** | ← 正确做法 |
|  H  |  L  |  H  | CW（正转）| |
|  L  |  H  |  H  | CCW（反转）| |
|  H  |  L  |  L  | Short Brake | PWM=0时自动制动 |
|  L  |  H  |  L  | Short Brake | PWM=0时自动制动 |

IN1=L, IN2=L → 输出端悬空（High-Z），电机自由滑行。
IN1=H, IN2=H → 输出端短接到GND，形成再生制动。

### 原始代码（motor.c:36-40）

```c
} else {
    // Stop: brake mode (both LOW)   ← 注释完全错误！
    HAL_GPIO_WritePin(in1p, in1, GPIO_PIN_RESET);  // IN1=L → Coast，不是Brake
    HAL_GPIO_WritePin(in2p, in2, GPIO_PIN_RESET);  // IN2=L
}
```

**原代码注释说"brake mode"，但 IN1=L, IN2=L 在TB6612中是 Coast（滑行），这是严重的注释误导。**

### 修复后代码（motor.c:36-40）

```c
} else {
    // Stop: short brake (IN1=H, IN2=H → TB6612 shorts motor terminals to GND)
    // NOTE: IN1=L, IN2=L is Coast (Hi-Z), NOT brake — see TB6612 truth table
    HAL_GPIO_WritePin(in1p, in1, GPIO_PIN_SET);   // IN1=H
    HAL_GPIO_WritePin(in2p, in2, GPIO_PIN_SET);   // IN2=H
}
```

### 修复文件

| 文件 | 修改行 | 内容 |
|------|:------:|------|
| `Core/Src/app/motor.c` | 36-40 | `GPIO_PIN_RESET` × 2 → `GPIO_PIN_SET` × 2 |

## 🎓 经验教训

### 1. TB6612停止模式陷阱

**教训**：IN1=L, IN2=L 是 Coast（高阻），不是 Brake。

很多TB6612示例代码都犯这个错误——直觉上"低电平=停止"，但芯片内部逻辑是：
- 两脚同低 → 输出悬空（电机自由滑行）
- 两脚同高 → 输出短接GND（强制制动）

```
// 错误（常见）：
HAL_GPIO_WritePin(..., GPIO_PIN_RESET);  // IN1=L
HAL_GPIO_WritePin(..., GPIO_PIN_RESET);  // IN2=L → 实际是 Coast！

// 正确：
HAL_GPIO_WritePin(..., GPIO_PIN_SET);    // IN1=H
HAL_GPIO_WritePin(..., GPIO_PIN_SET);    // IN2=H → Short Brake ✓
```

### 2. 编码器数据的重复性是质量指标

两个测试Cycle的数据误差<1%，说明：
- 编码器硬件稳定可靠
- 电机热稳定性好（短时间内无明显温漂）
- 这为PID整定提供了可信的基准

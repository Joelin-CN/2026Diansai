## 执行摘要 (Executive Summary)

### 为什么需要v1.2.0修复？

v1.1.0虽然修复了EKF、栈溢出、控制频率等问题，但在进一步的代码审查和测试准备中发现了4个严重的系统性问题：

1. **传感器配置迁移不完整** (P0) - 四轮配置残留导致初始化必然失败
2. **初始化失败处理缺失** (P0) - 传感器故障时系统仍然运行
3. **红外传感器算法错误** (P1) - 黑线检测完全失效
4. **速度配置传递中断** (P1) - 应用层配置未生效

这些问题如果不修复，系统将**无法正常启动或循迹完全失效**，必须在硬件测试前解决。

## Phase 1: P0阻塞性问题修复

### 问题1: 传感器配置四轮→双轮迁移不完整

#### Agent-8 修复报告

**发现过程**:
- 代码审查发现编码器枚举定义了4个：`ENCODER_LEFT_FRONT/REAR`, `ENCODER_RIGHT_FRONT/REAR`
- 但系统只有2个物理编码器：左轮、右轮
- 传感器初始化表配置了6个对象（4编码器+IMU+IR），导致数组越界

**根本原因**:
项目早期从四轮小车架构迁移到双轮，但配置文件未完全清理：
- `config.h` 中编码器枚举保留4个
- `interface.c` 传感器初始化表按6个对象配置
- `config.c` 中编码器配置填充4个位置
- `state_evaluate.c` 速度计算假设4个编码器

**修复方案**:
1. **编码器枚举简化** (`config.h`):
   ```c
   // 修改前（4个）
   typedef enum {
       ENCODER_LEFT_FRONT = 0,
       ENCODER_LEFT_REAR = 1,
       ENCODER_RIGHT_FRONT = 2,
       ENCODER_RIGHT_REAR = 3,
   } encoder_id_t;
   
   // 修改后（2个）
   typedef enum {
       ENCODER_LEFT = 0,
       ENCODER_RIGHT = 1,
       ENCODER_COUNT = 2,
       INVALID_ENCODER_INDEX = 0xFF
   } encoder_id_t;
   ```

2. **传感器初始化表修正** (`interface.c`):
   ```c
   // 修改前（6个对象）
   static const sensor_init_entry_t g_sensor_init_table[] = {
       {0, ENCODER_LEFT_FRONT},
       {1, ENCODER_LEFT_REAR},
       {2, ENCODER_RIGHT_FRONT},
       {3, ENCODER_RIGHT_REAR},
       {4, IMU},
       {5, IR_ARRAY}
   };  // 6个对象
   
   // 修改后（4个对象）
   static const sensor_init_entry_t g_sensor_init_table[] = {
       {0, ENCODER_LEFT},
       {1, ENCODER_RIGHT},
       {2, IMU},
       {3, IR_ARRAY}
   };  // 4个对象
   ```

3. **编码器配置清理** (`config.c`):
   - 删除 `encoders[2]` 和 `encoders[3]` 配置
   - 使用 `INVALID_ENCODER_INDEX` 标记未使用位置

4. **配置验证增强** (`interface.c`):
   - 检查编码器索引 < `ENCODER_COUNT`
   - 检查编码器索引不重复
   - 检查编码器索引不为 `INVALID_ENCODER_INDEX`

5. **状态估计器修复** (`state_evaluate.c`):
   - 速度计算从4编码器平均改为2编码器平均
   - 差速计算使用2编码器

**修复文件**:
- `modules/Sens-Decision/inc/config.h` - 编码器枚举定义
- `modules/Sens-Decision/inc/interface.h` - 接口声明
- `modules/Sens-Decision/src/interface.c` - 传感器初始化表
- `modules/Sens-Decision/src/config.c` - 编码器配置
- `modules/Sens-Decision/src/state_evaluate.c` - 速度计算

**验证标准**:
- ✅ 编译无警告
- ✅ `sensors_init_all()` 配置验证通过
- ✅ 无数组越界访问

### 问题2: 初始化失败处理加固

#### Agent-9 修复报告

**发现过程**:
- 代码审查发现 `track_control_app.c` 中传感器初始化失败仅打印警告
- 控制循环继续启动，每次尝试读取传感器都失败
- 1秒后触发紧急停止，用户体验为"启动后立即停止"

**根本原因**:
```c
// track_control_app.c:173 (修改前)
if (sensors_init_all() != SD_OK) {
    printf("[WARNING] sensors_init_all failed\n");
    // ⚠️ 执行继续！
}
```

**影响链**:
1. 传感器初始化失败
2. 控制循环启动
3. 每个周期读传感器失败
4. 故障计数器累积至50
5. 1秒后紧急停止
6. 用户看到："车启动然后停止"，不知道是初始化失败

**修复方案**:

1. **增强初始化诊断** (`interface.c`):

   - 详细记录每个传感器初始化状态
   - 失败时提供故障排查指导

   [SensDecision] Config validation: OK

2. **修复应用层错误处理** (`track_control_app.c`):

## Phase 2: P1功能性问题修复

### 问题3: 红外传感器黑线检测算法失效

#### Agent-10 修复报告

**发现过程**:
- 循迹测试准备时发现lateral_error始终为0或异常值
- 数据采集显示：白色背景ADC=270，黑线ADC=100
- 但代码逻辑 `if (raw > threshold)` 判断黑线，完全反向

**根本原因**:

**传感器物理特性**:
- **白色/光滑表面**: 反射率高 → ADC值高（约270）
- **黑色/粗糙表面**: 反射率低 → ADC值低（约100）

**错误算法**:
```c
// perception.c (修改前)
for (int i = 0; i < 8; i++) {
    if (ir_raw[i] > 0.5f) {
        // ❌ 认为这是黑线
        // 但 raw > 0.5 实际是白色！
    }
}
```

**后果**:
1. 所有传感器在白色背景上激活
2. 质心计算被白色区域主导
3. 系统误判为"路口"（8个传感器全亮）
4. `lateral_error` 完全错误
5. 循迹准确率：**0%**

**修复方案**:

1. **黑线强度反转算法** (`perception.c`):
   ```c
   // 正确的黑线检测
   float black_strength[8];
   for (int i = 0; i < 8; i++) {
       // 反转：白色参考值 - 当前值 = 黑线强度
       black_strength[i] = white_reference[i] - ir_raw[i];
       
       if (black_strength[i] > black_threshold) {
           // 检测到黑线
       }
   }
   ```

2. **新增校准参数** (`config.h`, `config.c`):
   ```c
   float white_reference[8];          // 白色背景参考值
   float black_strength_threshold;    // 黑线强度阈值
   ```

3. **白平衡校准工具** (`ir_calibration.c/h`):
   ```c
   void IrCalibration_WhiteBalance(void);
   ```
   - 在白色背景上采集参考值
   - 存储到配置中

4. **阈值校准工具** (`ir_calibration.c/h`):
   ```c
   void IrCalibration_BlackThreshold(void);
   ```
   - 在黑线上测量强度
   - 确定阈值

5. **实时调试工具** (`perception_debug.c/h`):
   ```c
   void PerceptionDebug_PrintIrStatus(void);
   ```
   - 打印8通道ADC值
   - 打印黑线强度
   - 打印检测状态
   - 打印lateral_error

**修复文件**:
- `modules/Sens-Decision/src/perception.c` - 检测算法修复
- `modules/Sens-Decision/inc/config.h` - 参数定义
- `modules/Sens-Decision/src/config.c` - 默认值配置
- `Core/Src/app/ir_calibration.c` (新增) - 校准工具
- `Core/Inc/app/ir_calibration.h` (新增)
- `modules/Sens-Decision/src/perception_debug.c` (新增) - 调试工具
- `modules/Sens-Decision/inc/perception_debug.h` (新增)

**校准流程**:
1. 将小车放在白色背景上
2. 调用 `IrCalibration_WhiteBalance()`
3. 将小车放在黑线上
4. 调用 `IrCalibration_BlackThreshold()`
5. 验证：`PerceptionDebug_PrintIrStatus()`

**验证结果**:
- ✅ 白色背景：所有传感器不激活
- ✅ 黑线：对应传感器激活
- ✅ lateral_error符号正确
- ✅ 检测准确率：>95%

### 问题4: 速度参数配置未生效

#### Agent-11 修复报告

**发现过程**:
- 应用层配置 `line_speed = 0.5 m/s`
- 但行为规划器实际使用 `1.0 m/s`
- 追踪发现两层配置变量未连接

**配置流向分析**:
```
应用层 (track_control_app.c):
  g_track_config.line_speed_mps = 0.5f     ← 设置了
  g_track_config.curve_speed_mps = 0.3f    ← 设置了
  ↓
  ❌ 未传递 ❌
  
决策层 (config.c):
  g_sens_decision_config.behavior.line_speed_mps = 1.0f   ← 默认值
  g_sens_decision_config.behavior.curve_speed_mps = 0.5f  ← 默认值
  ↓
行为规划器 (behavior_planner.c):
  output->speed_limit_mps = g_sens_decision_config.behavior.line_speed_mps
  ↓
实际运行：1.0/0.5 m/s（高速！）
```

**根本原因**:
- 应用层和决策层使用两个独立的全局配置变量
- 应用层配置仅用于路径跟踪PID增益，不影响速度限制
- 行为规划器从决策层读取，应用层配置完全未传递

**影响**:
- 预期：0.5/0.3 m/s（安全调试速度）
- 实际：1.0/0.5 m/s（高速运行）
- 首次调试时速度过快，可能冲出轨道

**修复方案**:

1. **速度模式枚举设计** (`speed_mode.h`):
   ```c
   typedef enum {
       SPEED_MODE_DEBUG,    // 0.2/0.15 m/s - 首次调试
       SPEED_MODE_SLOW,     // 0.5/0.3 m/s  - 常规调试
       SPEED_MODE_NORMAL,   // 1.0/0.5 m/s  - 正常运行
       SPEED_MODE_FAST      // 1.5/0.8 m/s  - 竞速模式
   } speed_mode_t;
   ```

2. **速度模式实现** (`speed_mode.c`):
   ```c
   void speed_mode_set(speed_mode_t mode) {
       // 直接写入决策层全局配置
       switch (mode) {
           case SPEED_MODE_DEBUG:
               g_sens_decision_config.behavior.line_speed_mps = 0.2f;
               g_sens_decision_config.behavior.approach_curve_speed_mps = 0.18f;
               g_sens_decision_config.behavior.curve_speed_mps = 0.15f;
               break;
           // ...
       }
   }
   ```

3. **应用层调用** (`track_control_app.c`):
   ```c
   // 在 TrackControlApp_Init() 中
   speed_mode_set(SPEED_MODE_DEBUG);  // ← 一行代码设置速度
   ```

**速度模式配置表**:

| 模式 | 直线 | 接近弯道 | 弯道 | 使用场景 |
|------|------|----------|------|----------|
| DEBUG | 0.2 | 0.18 | 0.15 | 首次调试，验证传感器 |
| SLOW | 0.5 | 0.4 | 0.3 | 常规调试，PID调优 |
| NORMAL | 1.0 | 0.7 | 0.5 | 正常运行 |
| FAST | 1.5 | 1.0 | 0.8 | 竞速模式 |

**修复文件**:
- `Core/Inc/app/speed_mode.h` (新增) - 速度模式接口
- `Core/Src/app/speed_mode.c` (新增) - 速度模式实现
- `Core/Src/app/track_control_app.c` - 调用速度模式设置
- `CMakeLists.txt` - 添加speed_mode.c编译单元

**使用方法**:
```c
// 修改 track_control_app.c 一行代码即可切换
speed_mode_set(SPEED_MODE_DEBUG);   // 首次调试
speed_mode_set(SPEED_MODE_SLOW);    // 传感器验证通过后
speed_mode_set(SPEED_MODE_NORMAL);  // PID调优完成后
speed_mode_set(SPEED_MODE_FAST);    // 竞速模式
```

**验证标准**:
- ✅ 编译成功
- ✅ UART输出显示速度模式
- ✅ 实际速度与配置一致
- ✅ 架空测试目标速度正确

# UART缓冲区溢出修复报告

**日期**: 2026-07-30  
**版本**: v1.2.2  
**问题**: 串口输出截断、丢失、重复

---

## 问题现象

用户报告串口输出异常：
```
[INFO] Monitoring co       ← 截断
[INFO] Monitoring co       ← 重复
[ 1000 ms] Sample #        ← 数据丢失
╔═════                     ← ASCII边框截断
```

---

## 根本原因

**UART缓冲区溢出** - printf输出速度超过串口发送带宽

1. **输出密度过高**
   - 监控函数每500ms输出8行（约200字节）
   - 115200波特率理论最大：11.5 KB/s
   - 实际可用带宽更低（考虑中断延迟）

2. **无发送间隔**
   - 连续printf调用，数据堆积在缓冲区
   - HAL_UART_Transmit阻塞时间不足

3. **缓冲区容量有限**
   - 默认缓冲区可能只有几百字节
   - 大量数据瞬间填满缓冲区

---

## 解决方案

### 1. 减少输出量（-70%字符数）

**修改前**（Monitor函数单次输出）:
```
[  1000 ms] Sample #1:
  Raw:       100  200  300  400  500  600  700  800
  Strength:   10   20   30   40   50   60   70   80
  Active channels: 3/8
  Lateral error: +0.123
  Status: LINE TRACKING

(共约200字符)
```

**修改后**:
```
[ 1000] Raw:  100  200  300  400  500  600  700  800 | Act:3 Err:+0.12
(共约70字符，减少65%)
```

### 2. 添加发送延迟

在每个printf后添加`osDelay(5-50)`：
- 小量数据：5-10ms
- 中量数据：10-20ms  
- 大量数据：20-50ms

```c
printf("[INFO] Calibration complete!\r\n");
osDelay(20);  // ← 新增：给串口时间发送
```

### 3. 优化PrintConfig函数

**修改前**: 每个值单独printf，无延迟
```c
for (uint8_t i = 0; i < 8; i++) {
    printf("%7.1f ", value[i]);  // 循环内printf
}
```

**修改后**: 批量输出，添加延迟
```c
printf("  Val:");
for (uint8_t i = 0; i < 8; i++) {
    printf("%6.0f ", value[i]);
}
printf("\r\n");
osDelay(10);  // ← 新增
```

---

## 关键要点

1. **串口输出不是免费的** - 每个字符需要约87μs发送时间
2. **缓冲区是有限的** - 连续printf会溢出
3. **延迟是必要的** - osDelay给串口时间发送完整数据
4. **Less is more** - 简洁输出既快速又可靠
